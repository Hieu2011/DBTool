# DbStudio

DB client cá nhân trên Windows (kiểu DBeaver): exe WinForms nhúng WebView2, bên trong chạy Kestrel loopback + UI React/Monaco. Hỗ trợ PostgreSQL, Oracle, MongoDB và Redis.

Chi tiết kiến trúc, API, hành vi query, lộ trình: xem [README.md](README.md) — đọc trước khi làm tính năng mới, không lặp lại ở đây.

@TaskList/task.md

## Lệnh

```powershell
.\scripts\dev.ps1                         # Vite (5173) + dotnet watch --dev (API 5280, không token)
dotnet build DbStudio.sln                 # build backend
cd web; npm run typecheck                 # tsc -b, kiểm tra UI
cd web; npm run build                     # tsc + vite build → src/DbStudio.Host/wwwroot
.\scripts\release.ps1 [-Version 1.2.0] [-Notes "..."]   # publish + đẩy lên thư mục update (WebDAV; chạy `-SaveCredential` một lần để lưu tài khoản cloud, DPAPI)
.\scripts\publish.ps1 [-FrameworkDependent] [-Notes "..."]   # ra dist\DbStudio.exe (single file, nén ~95 MB) + dist\version.json
```

- Chưa có test project, chưa có lint. Kiểm tra sau khi sửa = `dotnet build` + `npm run typecheck`.
- Chạy thử thật (UI + DB, kể cả exe đóng gói) theo `TaskList/20261127-test-ui-that/task.md`: `DBSTUDIO_DATA_DIR` đổi thư mục dữ liệu của app (`AppPaths.cs`) để không đụng connection thật; không dùng SendKeys khi tự động hoá hộp thoại.
- `tsconfig` bật `noUnusedLocals` / `noUnusedParameters`: biến/param thừa là lỗi build.
- Đang chạy `dev.ps1` / `DbStudio.exe` thì `dotnet build` có thể lỗi file bị khoá — tắt app rồi build lại, không phải lỗi code.

## Bố cục

| Project | Target | Vai trò |
|---|---|---|
| `src/DbStudio.Core` | net8.0 | Model + `IDbProvider`, `IConnectionStore`. Không tham chiếu driver nào. |
| `src/DbStudio.Providers` | net8.0 | `AdoProviderBase` + `PostgresProvider`, `OracleProvider`, `ProviderRegistry`. |
| `src/DbStudio.Host` | net8.0-windows | Exe: `Program` → `ApiHost` (Kestrel, DI, token) → `MainForm` (WebView2); `Api/DbStudioApi.cs` chứa toàn bộ endpoint. |
| `web/` | Vite + React 19 + Tailwind v4 | UI, build thẳng vào `wwwroot` của Host. |

Chiều phụ thuộc: Host → Providers → Core. Giữ Core sạch (không Npgsql/ODP.NET/WinForms).

## Điều dễ sai

- **UI nhúng dạng embedded resource.** Sửa `web/` xong phải `npm run build` rồi build lại Host thì bản chạy không `--dev` mới thấy thay đổi. `wwwroot/` bị gitignore (trừ `.gitkeep`), không sửa tay trong đó.
- **Contract C# ↔ TS đồng bộ bằng tay:** `src/DbStudio.Core/Models.cs` ↔ `web/src/types.ts`. JSON camelCase, enum serialize dạng chuỗi (`JsonStringEnumConverter`) nên tên `DbKind` hai bên phải khớp từng ký tự.
- **Lỗi trả về UI luôn là `QueryError`** (`message`, `position?`, `code?`); `api.ts` ném `ApiError` cho mọi response non-2xx. Endpoint mới giữ đúng dạng này.
- **Giá trị cell phải đi qua `AdoProviderBase.Normalize`** (decimal/long lớn → string, bytes → hex cắt 64 byte...). Kiểu driver đặc thù thì override `ReadValue`, không trả object thô ra JSON.
- **Cắt dòng / huỷ query:** phải gọi `DbCommand.Cancel()` trước khi dispose reader, nếu không driver kéo hết phần còn lại. Đừng "dọn" đoạn `finally` trong `ExecuteAsync`.
- **Không dùng `localStorage` để lưu cài đặt:** bản release chạy port ngẫu nhiên nên origin đổi mỗi lần mở, dữ liệu mất. Cài đặt cần giữ phải lưu phía server (`%APPDATA%\DbStudio`).
- **Sidebar là một cây cuộn chung kiểu DBeaver** (`ConnectionList.tsx`): connection là nút gốc, cây của nó (`renderTree` của `App.tsx`) nằm ngay dưới, một ô lọc dùng chung cho mọi cây (`TreeControl`), nút Refresh nằm trên dòng connection. Cây không tự cuộn: `ObjectTree` / `RedisTree` virtualize theo scroller của sidebar (`useOuterScroll`: tìm `data-tree-scroll`, đo `scrollMargin`, dòng vẽ ở `start - margin`). Dòng connection `sticky` cao đúng `TREE_STICKY_TOP` (36px) — đổi chiều cao thì sửa cả hằng số; đừng đặt `overflow-hidden` lên phần tử bọc cây (mất sticky). Cây chỉ mount khi connection được mở lần đầu (mount là kết nối DB) và giữ mount khi thu gọn (`hsMounted`); `objReveal` chỉ truyền cho cây của tab đang mở.
- **Phiên làm việc giữ qua lần tắt app** (`WorkspaceStore`, `workspace.json`, `GET/PUT /workspace`): chỉ tab editor (text kể cả chưa lưu, connection, file, tab đang chọn), giữ 7 ngày kể từ lần lưu cuối. UI lưu sau mỗi thay đổi (trễ 600 ms) và `MainForm.FormClosing` gọi `window.__dbstudioSaveTabs` (request đồng bộ) trước khi đóng thật. Không được lưu trước khi đọc xong phiên cũ (`refRestored`), nếu không phiên cũ bị ghi đè bằng danh sách rỗng. Tab khôi phục không tự kết nối (`boolLazyConnect`), trừ tab đang chọn. Đổi connection của tab (combobox trên toolbar) = remount `QueryWorkspace` (key `tab.id:connectionId`) với text hiện tại.
- **Tab ≠ connection:** `App.tsx` giữ `arrTabs`; một connection có nhiều tab, `QueryWorkspace` key theo `tab.id`, metadata cache theo `connection.id`.
- **Session theo tab:** UI gửi `sessionId`; `SessionRegistry` giữ một `IDbSession` (connection mở) cho mỗi tab, mỗi session chỉ chạy 1 statement một lúc. `AdoSession` là nested class trong `AdoProviderBase` (`AdoSession.cs`). Không có `sessionId` thì `/query` chạy connection dùng một lần.
- **Transaction PostgreSQL bọc savepoint mỗi statement** (`SavepointPerStatement`): lỗi hoặc `Cancel()` khi cắt dòng sẽ abort cả transaction nếu thiếu savepoint. `EndSavepointAsync` không được ném exception.
- **Object explorer:** SQL catalog nằm trong `PostgresProvider.Objects.cs` / `OracleProvider.Objects.cs`. Thêm lưới chi tiết = thêm một câu vào `SectionQueries`; tham số bind theo tên `schema`, `name`, `signature` (PG `@`, Oracle `:`), không nối chuỗi. `ObjectsSql` trả đúng 4 cột `schema, name, type, signature`. Cây (`ObjectTree.tsx`, `OBJECT_FOLDERS`) lấy thư mục con theo `Title` của section và hiện cột 1 làm tên, cột 2 làm ghi chú — đổi title hoặc thứ tự 2 cột đầu thì sửa cả hai phía. Lưới chậm (code dùng bảng: `ALL_DEPENDENCIES`, quét `prosrc`) đặt trong `OnDemandSectionQueries`: chỉ chạy cho tab chi tiết hoặc khi cây gọi `?section=<Title>`; thứ tự cột của chúng (`USED_BY_FOLDERS`) là Oracle `name, owner`, PostgreSQL `name, arguments, schema`. `ByNameSectionQueries` là loại thứ ba: chỉ chạy khi gọi đúng `?section=<Title>`, không kèm tab chi tiết; `Relations` (cột `direction, constraint, schema, table, columns, other_columns`) nuôi tab Diagram (`TableDiagram.tsx`); `InferredRelations` cùng dạng cột, đoán quan hệ theo tên cột trùng khoá chính cho DB không khai báo FK (lỗi của nó không được làm hỏng phần FK thật). Diagram của procedure/function (`RoutineDiagram.tsx`) dùng `RoutineTables` (`schema, table, primary_key`) + `RoutineRelations` (`schema, table, columns, ref_schema, ref_table, ref_columns, constraint`); PostgreSQL không có dependency cho thân hàm nên dò tên bảng trong `prosrc`. Mọi diagram vẽ qua `DiagramCanvas.tsx`; vị trí kéo thả lưu phía server bằng `DiagramLayoutStore` (`diagram-layouts.json`, khoá `connectionId|tên diagram`), xoá connection thì xoá theo. Lỗi DDL / lỗi danh sách object phải trả về dạng `DdlError` / `ObjectsError`, không ném ra làm hỏng phần còn lại.
- **Oracle load metadata từng schema:** `MetadataSql` / `ObjectsSql` nhận `:schema` (null = schema đăng nhập); `SchemasSql` + `CurrentSchemaSql` bật chế độ này. `SchemaMetadata.Schemas` là mọi schema, `Tables`/`Objects` chỉ gồm `LoadedSchemas`; endpoint metadata `?schema=X` load thêm và `Merge` vào cache. Đừng đổi sang quét cả instance.
- **Chạy routine** (`*.Routines.cs`, tab `RoutineRunner`): kiểu tham số luôn lấy lại từ catalog phía server (`RoutineParametersSql`: `position, name, data_type, mode`), client chỉ gửi vị trí + chuỗi giá trị. PostgreSQL chạy trong transaction để `FETCH` refcursor và dùng `FETCH n+1`, không `Cancel()` (cancel abort transaction, mất phần hàm đã ghi). Store MWG trên PG có dạng `INOUT v_out refcursor` + `RETURNS refcursor`. Cast tham số phải qua `CastType` (`character` trần = `char(1)`, cắt giá trị). Editor Auto-commit: `PostgresProvider.ExecuteAutoCommitAsync` bọc câu `SELECT …(` trong transaction ngắn và trả dữ liệu cursor khi mọi cột kết quả là `refcursor`. Editor Oracle: `BindEditorParameters` bind mọi `:tên` trong block `BEGIN`/`DECLARE`/`CALL` thành `OUT RefCursor` (không áp dụng cho `CREATE …` vì `:new`/`:old`), `ReadOutputCursorsAsync` đọc lại. Cursor thứ hai trở đi nằm trong `QueryResult.More` (↔ `more` ở `types.ts`), UI mở mỗi cái một tab.
- **Sửa cấu trúc bảng** (`TableEditor.tsx`, `KeysEditor.tsx` cho constraint/index, màn chạy chung `ScriptReview.tsx`, SQL ở `web/src/sql/alterTable.ts`; `KeysEditor` lấy cột đầu của lưới Constraints/Indexes làm tên): SQL sinh ở client từ lưới Columns theo tên cột `column, type, nullable, default, comment` (đổi tên các cột này ở provider thì sửa cả `toDrafts` và `ColumnProperties`). Không chạy thẳng: luôn qua màn Review. Đổi thứ tự cột không có `ALTER` nào làm được: `buildRebuildScript` sinh script dựng lại bảng và chỉ mở qua Script changes, đừng nối nó vào Apply. Cú pháp Oracle phải chạy được trên 11g.
- **Xuất dữ liệu:** lưới xuất dòng đang hiện ở client (`web/src/exportData.ts`, tự ghi xlsx). Xuất cả bảng đi qua `POST /export`: `AdoProviderBase.StreamAsync` đẩy từng dòng vào `IRowSink` (`ExportSinks.cs`), file ghi phía server, không gom dòng trong RAM. Hai nơi ghi xlsx phải cho ra cùng định dạng (số chỉ khi ≤ 15 chữ số, còn lại là chuỗi). **Đường dẫn ghi không do UI tự đặt:** UI gọi `POST /export/pick` để mở `SaveFileDialog` (`ExportTargets`, chạy trên UI thread của `MainForm`), `/export` chỉ ghi vào đường dẫn hộp thoại vừa trả về (dùng một lần), `/export/reveal` chỉ mở file đã xuất trong phiên chạy này — đừng nới các kiểm tra đó. File do UI tự tạo (blob download: xuất lưới, ảnh diagram) đi qua `DownloadStarting` trong `MainForm`, cũng hỏi nơi lưu.
- **Menu ứng dụng + file `.sql`:** menu khai báo trong `App.tsx` (`arrMenus`), vẽ bằng `MenuBar.tsx`; phím tắt toàn cục đi qua `refShortcuts` (thêm mục menu có phím tắt thì thêm cả ở đó). Menu điều khiển editor qua `EditorHandle` mà `QueryWorkspace` đăng ký bằng `onHandle`, không gọi thẳng Monaco từ `App`. File đọc/ghi ở server (`SqlFiles.cs`): UI không tự đặt đường dẫn, `/files/save` chỉ ghi đè đường dẫn mà hộp thoại Open/Save đã trả về trong phiên chạy này. Tab file là tab `query` có `title` + `filePath`; vẫn gắn với một connection.
- **Import dữ liệu** (`TableImport.tsx`, `web/src/importData.ts`): file đọc ở client, không có endpoint riêng. Các câu `INSERT` chạy lần lượt qua `/query` với một `sessionId` tạm và `autoCommit: false`, commit một lần ở cuối, lỗi/Stop thì rollback rồi đóng session — đừng đổi sang auto-commit từng câu (mất tính tất-cả-hoặc-không). Giá trị là literal do `sqlLiteral` sinh; Oracle phải bọc ngày bằng `TO_DATE`/`TO_TIMESTAMP` vì phụ thuộc NLS.
- **Số dòng cạnh tên bảng trên cây** là ước lượng từ thống kê (`RowCountsSql`: `schema, table, rows` → `TableMeta.Rows`; PG `reltuples`, Oracle `ALL_TABLES.NUM_ROWS`, Mongo `EstimatedDocumentCountAsync`). PostgreSQL đếm thật (`count(*)` qua `query_to_xml`) riêng bảng dưới 4 MB vì thống kê của bảng nhỏ hay là 0 — đừng nới ngưỡng này, bảng lớn chỉ dùng ước lượng; lỗi ở câu này bị nuốt, không được làm hỏng metadata.
- **`MetadataSql`** bắt buộc trả 5 cột đúng thứ tự `schema, table, object_type, column, data_type`, sắp theo schema, table, vị trí cột. SQL metadata Oracle phải chạy được trên 11g.
- **Server luôn nhận 1 statement mỗi request.** Chạy nhiều câu là việc của UI (`QueryWorkspace.execute`): tách, gửi tuần tự qua session của tab, dừng ở lỗi đầu. Đừng chuyển sang batch phía server: Oracle không nhận batch, và `Cancel()` khi cắt dòng sẽ huỷ cả batch PostgreSQL.
- **Tách statement** (`web/src/sql/statements.ts`): bộ từ khoá block PL/SQL phải khớp với `OracleProvider.PlSqlStart`; statement bắt đầu ở ký tự code đầu tiên (bỏ comment đứng trước) vì regex phía server neo ở đầu chuỗi. Sửa xong chạy `node TaskList/20261119-statement-tai-con-tro/statements.check.ts`.
- **Stream kết quả:** editor gọi `POST /query/stream` (NDJSON: `columns`, `rows`, cuối là `done` hoặc `error`; đã bắt đầu thì luôn HTTP 200, lỗi nằm trong dòng `error`). Dòng đi qua `IRowSink` tuỳ chọn của `ExecuteAsync`; có sink thì `QueryResult.Rows` rỗng và cờ `streamed` báo UI lấy dòng từ stream. Kết quả provider tự dựng (mở refcursor) không qua sink — đừng truyền sink vào nhánh `SelectCall` của PostgreSQL. `/query` thường vẫn dùng cho lưới Data, import, script DDL.
- **Cài đặt + history phía server:** `SettingsStore` (`settings.json`: vị trí cửa sổ do `MainForm` ghi, phần `Ui` do UI ghi qua `GET/PUT /settings`), `HistoryStore` (`history.json`, chỉ câu editor báo về qua `POST /history`; xoá connection thì xoá theo). Lỗi ghi hai file này không được làm hỏng thao tác chính. Snippet: `SnippetStore` (`snippets.json`, `PUT /snippets` thay cả danh sách); UI giữ danh sách trong `web/src/sql/snippets.ts` để `completion.ts` gợi ý theo prefix, chèn bằng cú pháp snippet của Monaco (`$` thật phải viết `\$`).
- **MongoDB** (`MongoProvider*.cs`, `MongoShell.cs`): implement thẳng `IDbProvider`, không qua `AdoProviderBase`. Database đóng vai schema (load từng cái như Oracle), collection là `TableMeta` type `COLLECTION` / `VIEW`, cột = field lấy mẫu. Statement là chuỗi lời gọi kiểu mongo shell do `MongoShell.Parse` đọc, đối số đọc bằng BSON reader của driver. Câu nào parser không đọc được hoặc dùng thứ chỉ JavaScript có thì ném `MongoShellException` mã `Script` và `RunAsync` chuyển sang `ScriptHost` (`MongoProvider.Script.cs`, Jint): chỉ gắn mã `Script` cho lỗi xảy ra **trước khi** gửi gì lên server, nếu không câu lệnh sẽ chạy hai lần. Engine là sandbox (không bật CLR interop — giữ nguyên), shell object (`db`, cursor, `ObjectId`…) viết bằng JS trong `Bootstrap`; giá trị qua lại giữa JS và C# ở dạng text shell (`ShellJson(..., boolScript: true)` ↔ `toShell`), mọi lời gọi DB đi qua `__run` → `RunCommandAsync` nên dùng chung luật với câu thường; giá trị BSON gốc của kết quả nằm trong `RawResults` (`WithRaw`) — thêm method mới thì nhớ gắn. Mỗi tab một engine (biến giữ giữa các câu; `const` / `let` cấp ngoài cùng đổi thành `var` trong `KeepDeclarations`). Tách câu ở client (`splitStatements` dialect `mongo`) chỉ cắt ở `;` ngoài mọi ngoặc. `deleteOne/deleteMany` không có filter phải báo lỗi, không được hiểu là xoá hết. JSON in ra phải qua `ShellJson` tự viết (writer của driver in double 17 chữ số). Transaction: `MongoSession` giữ một `IClientSessionHandle` khi auto-commit tắt; chỉ đọc / ghi document đi qua nó (tham số `objTx`), DDL và `runCommand` chạy ngoài. Server huỷ transaction ở mọi lỗi nên session cũng bỏ nó và báo rõ trong thông báo; standalone trả `QueryError.Code = "TransactionsUnavailable"` — UI dựa vào mã này (editor về Auto-commit, import chuyển sang insert thường), đừng đổi tên. Import collection (`CollectionImport.tsx`, `importDocuments.ts`) sinh `insertMany` bằng cú pháp shell, không có endpoint riêng. Kết quả document trả kèm `QueryResult.Documents` (↔ `documents`) cho nút Grid / JSON. UI: câu lệnh do UI tự sinh đi qua `web/src/sql/dialect.ts` (`selectAllQuery`, `countQuery`, `dialectOf`, `editorLanguage`), đừng nối `SELECT ...` trực tiếp trong component; editor Mongo dùng language `mongodb` (khai báo trong `monaco.ts`) và `mongoCompletion.ts`, không dùng parser SQL / format SQL (`isSqlKind`); nút Auto-commit / Manual theo `hasTransactions`.
- **Redis** (`RedisProvider.cs`): implement thẳng `IDbProvider`. Statement là một dòng lệnh redis-cli (`splitStatements` dialect `redis` tách theo dòng, không theo `;`). Một `ConnectionMultiplexer` dùng chung cho mọi tab nên: `SELECT` chỉ đổi số database nhớ trong session, và các lệnh chặn / cần kết nối riêng (`Refused`) phải bị từ chối — đừng nới danh sách đó. Ép `Protocol = Resp2` để dạng reply ổn định (RESP3 lồng cặp và thêm tiền tố `txt:` cho INFO). Key không nằm trong metadata: `RedisTree.tsx` gọi `/redis/databases` + `/redis/keys` (SCAN theo cursor, không bao giờ `KEYS *`); `RedisProvider` đăng ký DI bằng cả kiểu riêng lẫn `IDbProvider`. Cluster: `ClusterMasters` khác rỗng thì SCAN lần lượt từng master (cursor `node:cursor`), chỉ có db 0; lệnh của viewer truyền key dạng `RedisKey` để driver định tuyến đúng node, lệnh console dựa vào MOVED. Sửa value (`RedisValueEditor.tsx`) sinh lệnh ở client bằng `redisQuote` (escape phải khớp `SplitCommand`: `\n \r \t \xHH`) và chạy qua `/query` trên session tạm sau `SELECT n`. Thêm key (`RedisNewKey.tsx`: `EXISTS` trước, key đã có thì từ chối, không ghi đè) và xoá hàng loạt nằm ở cây: xoá theo thư mục phải SCAN lại theo prefix (escape ký tự glob, `prefixPattern`) chứ không dùng danh sách đã tải, tối đa 100.000 key, `DEL` 100 key mỗi lệnh và gặp `CROSSSLOT` thì xoá từng key; luôn `confirm` kèm số key. Key mở bằng tab object thường (`DbObjectInfo` schema `dbN`, type `STRING`/`HASH`/…), `LoadObjectAsync` trả section `Value` + `Properties`, ô DDL chứa các lệnh đọc key.
- **Sửa dữ liệu trên lưới** (`EditableResult.tsx`, `web/src/sql/editData.ts`, `AdoProviderBase.Edit.cs`): cột nào thuộc bảng nào phải lấy từ driver (`DescribeResultAsync`: `SchemaOnly | KeyInfo`, không chạy câu lệnh), không đoán theo tên cột — đoán sai là `UPDATE` nhầm bảng / nhầm dòng. `UPDATE` luôn theo đủ khoá chính đọc từ chính dòng đó (`rowEditable`: khoá phải đủ và giống nhau ở mọi cột lặp lại, vì self-join), Save chạy thẳng (anh đã chọn bỏ bước Review và cả khung hiện câu lệnh 2026-11-20; câu lệnh chỉ còn trong tooltip của nút Save), và phải kiểm `recordsAffected === 1`. Không biết bảng nguồn / không có PK thì không cho sửa (an toàn hơn là cho sửa sai). Đó là đường PostgreSQL. **Oracle** không đi đường này (ODP.NET không trả bảng nguồn): `oracleEdit.ts` đọc `FROM` và select list từ text (`parseSelect`, `mapColumns` — phải khớp đủ số cột và tên cột với kết quả, không khớp thì không cho sửa), chạy lại câu lệnh với `<bảng>.ROWID AS DBSTUDIO_ROWID_` (`rowIdSql`) rồi `UPDATE … WHERE ROWID`; file này chỉ import `derived.ts` để chạy được bằng node. Ô trống nghĩa là NULL (`sqlLiteral`; chuỗi ngoài ASCII vào cột `N*` của Oracle phải ra `UNISTR`, literal thường đi qua charset của DB). UI: lưới sửa được ngay, thanh dưới có Save / Cancel / thêm / duplicate / xoá dòng + ô Table; thay đổi chờ gồm `dicChanges` (ô của dòng đã tải, khoá `row:col`), `arrNew` (dòng mới, nằm cuối lưới từ `intBase`), `hsDeleted`. Save chạy trong transaction riêng, chỉ tab Manual mới chạy trên session của tab; có insert / delete thì đọc lại dữ liệu vì chỉ số dòng đổi. Oracle đọc ROWID ở lần sửa / xoá đầu tiên (`prepare`): dòng đọc lại khác dòng đang hiện thì bỏ thao tác đó — đừng bỏ bước so sánh này, số dòng có thể đã trỏ sang dòng khác. Cột nhị phân (`isBinaryType`: bytea / RAW / BLOB) nhập dạng hex `0x…` và luôn đi qua `decode(…, 'hex')` / `HEXTORAW` — không bao giờ thành literal chuỗi (PostgreSQL sẽ lưu byte của chính đoạn text); giá trị dài hơn 64 byte server đã cắt nên không sửa / duplicate được (`binaryHex` trả null). Ô chỉ nhận biểu thức qua danh sách trắng `EXPRESSION` trong `editData.ts` (`=SEQ.NEXTVAL`, `=SYSDATE`…), còn lại luôn là literal — đừng nới thành "mọi thứ sau dấu =". Dòng mới trên Oracle: cột khoá (PK một cột, không khai báo PK thì cột đầu) tự điền theo quy ước tên của MWG (`keyGeneratorSql`): store `<BẢNG>_NEWID` (procedure một tham số OUT → `INSERT` bọc trong block `DECLARE … BEGIN proc(v_1); INSERT …; END;`, `RowUpdate.block` vì driver không trả số dòng) rồi mới tới sequence `SEQ_<BẢNG>_ID`…
- **Tab bảng load hai nhịp** (`ObjectViewer`): gọi `objectDetail(…, false)` (lưới nhanh) và bản đầy đủ song song; bản nhanh hiện trước với cờ `partial`, bản đầy đủ (DDL, comment, lưới `OnDemandSectionQueries`) thay vào khi về. Đừng gộp lại một lần gọi: `DBMS_METADATA` + `ALL_DEPENDENCIES` làm tab trắng vài giây.
- **Điều hướng theo object:** F12 hoặc Ctrl + click trong editor (`dbstudio.goToObject`, `objectAt` ở `hover.ts`) mở tab của bảng / routine dưới con trỏ, schema Oracle chưa load thì load rồi thử lại. Cây (`ObjectTree` và `RedisTree`, prop `objReveal` = object của tab đang mở; Redis: đổi sang đúng `dbN`, mở các thư mục theo `:`, key chưa nằm trong các trang SCAN đã tải thì được thêm vào danh sách trừ khi đang lọc) tự mở schema / nhóm / object đó và cuộn tới; mỗi lần đổi tab chỉ thử một lần (`refRevealed`) để không giật lại khi người dùng tự thu gọn. Autocomplete chèn alias (chữ cái đầu mỗi từ của tên bảng) chỉ khi chọn bảng ngay sau `FROM` / `JOIN` và phía sau chưa có gì giống alias (`aliasFor`).
- **Sửa document MongoDB trên lưới** (`web/src/sql/mongoEdit.ts`, dùng chung `EditableResult`): chỉ kết quả của `db.<collection>.find(...)` có cột `_id`; chỉ field cấp ngoài cùng; cột `object` / `array` sửa được cả giá trị dạng text shell nhưng phải qua `documentLiteral` (một `{}` / `[]` chỉ chứa dữ liệu + constructor trong danh sách trắng) — đừng nới: text khác sẽ bị server chạy như script (Jint); giá trị dài hơn 20.000 ký tự server đã cắt (`…`) nên không lưu được; binary và cột nhiều kiểu vẫn khoá. Mỗi document tìm theo `_id` viết lại đúng kiểu (`idLiteral`; không viết lại được thì dòng đó khoá). `updateOne` phải kiểm `matchedCount === 1` (không phải `modifiedCount`: ghi lại giá trị cũ thì modified = 0). Câu lệnh chạy trên session của tab (database hiện tại + transaction nếu tab đang Manual), không bọc transaction riêng vì standalone không có. Sau khi đọc lại dữ liệu phải tính lại target (`mongoTarget`) vì cột của document không cố định.
- **Form chọn ngày giờ** (`DatePicker.tsx`, dùng ở ô ngày của lưới và tab Execute): kiểu shadcn — `react-day-picker` + `@radix-ui/react-popover` (anh duyệt 2026-11-20), class Tailwind theo token màu của app, không nạp stylesheet của thư viện. shadcn không cài nguyên bộ được: token `muted` của app là màu chữ, của shadcn là màu nền, nên component shadcn chép về phải đổi class (`text-muted-foreground` → `text-muted`…). Popover nằm ngoài ô (portal): lưới giữ `refPickerOpen` để blur khi đang mở lịch không kết thúc việc sửa ô.
- **Autocomplete tự load schema Oracle:** `withNamedSchemas` trong `completion.ts` load (một lần) những schema mà câu lệnh tại con trỏ nhắc tới (`tms.` đang gõ, `FROM tms.x`) qua `schemaLoaderFor` — không cần mở schema trên cây. Chỉ load schema được nêu tên, không quét cả instance; schema load lỗi thì không thử lại trong phiên.
- **Thứ tự gợi ý** (`sortText` trong `completion.ts`): cột `1`, bảng `2`, keyword `3`, routine `5`, snippet `0` ở đầu câu lệnh và `8` ở chỗ khác. Sau `FROM schema.` chỉ gợi ý bảng. Snippet hiện bằng `snippetLabel` (key + dòng code tóm tắt + mô tả).
- **Snippet dựng sẵn** (`web/src/sql/builtinSnippets.ts`: `seldt`, `seltop`, `upd`… theo từng dialect `oracle` / `pgsql` / `mongo` / `redis`): luôn có trong autocomplete của cả 4 loại, snippet của người dùng trùng prefix thì thay thế. Thân Oracle phải chạy được trên 11g; `$` thật viết `\\$`. Gợi ý cột chèn `alias.cột` khi bảng có alias trong câu (`columnItems(objTable, strAlias)`, trừ cột sau `SET` của PostgreSQL và khi đã gõ `x.`).
- **Format SQL** (`web/src/sql/format.ts`): chỉ được đổi khoảng trắng và hoa/thường của keyword. `formatStatement` tokenize lại kết quả và trả nguyên văn nếu lệch token — giữ bước kiểm này khi sửa luật dàn dòng. SQL thường do `sql-formatter` dàn (`formatDialect` + `postgresql` / `plsql`), bộ `layout` tự viết là dự phòng cho DML; code thủ tục (`isProcedural`) luôn trả nguyên vì thư viện tách nó ở từng `;` bên trong.
- **Gập dòng** (`web/src/sql/folding.ts`): chỉ bật cho model đã gọi `foldByStatement`; model khác provider trả `null` để Monaco gập theo thụt lề.
- **Autocomplete** (`web/src/sql/completion.ts`): giữ nguyên chữ ký `registerSqlCompletion(monaco)` và `metadataFor(model, getter)` khi thay engine. `dt-sql-parser` chỉ được import trong `parser.worker.ts` (import sâu từng dialect, không import gốc package: bundle chính sẽ phình và lần parse đầu khoá UI hơn 1 giây). Worker trả `SqlAnalysis` (`analysis.ts`); không có câu trả lời (timeout, cú pháp Oracle riêng, block PL/SQL) thì bộ regex bên dưới trả lời — đừng xoá nó. Thư viện không có dialect Oracle: Oracle dùng `GenericSQL` và chỉ tin phần ngữ cảnh bảng / cột của nó; cột của subquery / CTE khi parser không trả về thì đọc từ text bằng `derived.ts` (file này không import gì để chạy được bằng node). Hover + signature help ở `hover.ts` (không dùng parser; tham số routine Oracle lấy qua `routinesFor` → `api.routineInfo`, nhớ theo model).
- **Tự update** (`UpdateService.cs`, `UpdateDialog.tsx`, Help → Check for updates…): nguồn là link chia sẻ công khai của một thư mục Nextcloud / ownCloud chứa `DbStudio.exe` + `version.json` (`scripts/publish.ps1` sinh ra, có `sha256`); đọc qua `public.php/webdav/<file>` với Basic `token:mật khẩu`. Link là cài đặt của người dùng (`%APPDATA%\DbStudio\update.json`, mật khẩu DPAPI, API chỉ trả `hasPassword`) — không ghi link / mật khẩu vào code hay repo. Chỉ nhận `https`, không theo redirect, bắt buộc khớp SHA-256 mới cài; thay exe bằng cách đổi tên file đang chạy thành `.old` rồi chuyển file mới vào (xoá `.old` ở lần mở sau). Mỗi lần phát hành phải tăng `<Version>` trong `DbStudio.Host.csproj`. `scripts/release.ps1` làm trọn việc (tăng version, build, upload exe tên riêng rồi mới ghi `version.json`, thêm mục vào `CHANGELOG.md`); tài khoản cloud của nó nằm ở `%APPDATA%\DbStudio\release.xml` (DPAPI), không bao giờ trong repo. **Phát hành theo push:** hook `scripts/hooks/pre-push` (bật bằng `scripts\install-hooks.ps1`, tức `core.hooksPath`) chạy `release.ps1 -IfNewer` khi push lên `main` làm đổi `<Version>`; nó đòi working tree sạch và có mục `## <version>` trong `CHANGELOG.md` (nội dung mục đó là notes hiện trong app), release lỗi thì chặn push. Quy trình ra bản: tăng `<Version>` + viết mục changelog + commit, rồi push. File `.ps1` phải thuần ASCII (Windows PowerShell đọc file không BOM theo ANSI, ký tự như `—` làm vỡ chuỗi). App chỉ tự kiểm tra (không tự tải) lúc mở.
- **Đếm người dùng** (`UpdateService.Usage.cs`, `scripts/users.ps1`): khi `version.json` có trường `stats` (link chia sẻ kiểu chỉ-upload, cùng host với link update — khác host thì bỏ qua), mỗi lần check update app thả một file `MÁY_user_yyyyMMdd_vX.Y.Z.json` (user Windows, domain, máy, IPv4, OS, version) vào đó, tối đa một lần mỗi ngày và mỗi version (`usage.json`); mọi lỗi bị nuốt. Link `stats` là cài đặt của máy phát hành (`release.ps1 -SaveStatsLink` → `release.xml`), không nằm trong repo. Form Updates có dòng báo cho người dùng biết — đổi dữ liệu gửi đi thì sửa cả dòng đó.
- **Output của statement** (`QueryResult.Messages` ↔ `messages`): chỉ cho SQL gõ trong editor (`boolEditorSql` trong `ExecuteOnAsync`). PostgreSQL bắt `Notice` của connection; Oracle bật `DBMS_OUTPUT` trước và đọc `GET_LINE` sau, chỉ với block / `CALL` / `EXEC` (`CanPrint`) vì tốn thêm 2 round trip — hai hook đó không được ném exception. `EXEC proc(...)` được `PrepareSql` đổi thành block.
- **Biến `:tên` / `&tên` trong editor** (`web/src/sql/bindVariables.ts`, `BindDialog.tsx`): hỏi giá trị rồi thay thẳng vào text trước khi gửi, server không nhận tham số. Block Oracle (`BEGIN` / `DECLARE` / `CALL` / `EXEC`) giữ nguyên `:tên` vì server bind chúng thành OUT cursor; `&tên` chỉ có ở Oracle. Câu lệnh do UI tự sinh để tra catalog (tìm object, session, kill session) nằm trong `dialect.ts`.
- **Cuộn tải tiếp** (`IResumableSession`, `AdoSession.FetchMoreAsync`, `POST /query/more`, `EditableResult.fetchMore`): request có `keepOpen` + `sessionId` thì kết quả bị cắt ở `MaxRows` không bị `Cancel()` mà giữ nguyên command + reader trong session (`QueryResult.Cursor` ↔ `cursor`); reader đang đứng ở dòng đầu tiên chưa trả nên `ReadRowsAsync(boolResume: true)` trả dòng đó trước. Mọi lần dùng session khác (statement mới, commit, rollback, dispose) đóng cursor trước; đóng khi còn dòng = `Cancel()` rồi mới dispose. PostgreSQL Manual: savepoint của statement chỉ kết thúc khi cursor đóng; nhánh `SelectCall` giao transaction ngắn của nó cho cursor (`CursorSlot.Transaction`). `SessionRegistry` tự đóng cursor không ai đọc sau 5 phút (trên PostgreSQL nó giữ snapshot + lock bảng, chặn `ALTER`) — đừng bỏ; tab Data đóng session đọc của nó khi rời tab cũng vì lý do đó. UI: chỉ câu cuối của một lần chạy gửi `keepOpen`. Cursor mất (410, mã `CursorClosed`) thì đọc tiếp bằng cách chạy lại câu lệnh với `skipRows` = số dòng lưới đang có (`CursorSlot.SkipRows`: server đọc bỏ các dòng đó rồi giữ mở tiếp; không chèn `LIMIT` / `OFFSET` vào SQL): tab Data của bảng tự làm khi cuộn (`boolRerunOnScroll`, câu do app sinh), editor chỉ làm khi bấm More rows — đừng cho editor tự chạy lại khi cuộn, câu của người dùng có thể chậm hoặc có tác dụng phụ (`nextval`, hàm ghi dữ liệu). Dòng mới nối sau dòng đã tải nên không tải tiếp khi còn dòng đang thêm (`arrNew`). Chỉ `AdoSession` làm được; MongoDB / Redis vẫn dùng More rows kiểu cũ (chạy lại với limit ×5). Sửa xong chạy lại test ở `TaskList/20261126-cuon-tai-tiep/` (22 case, cần Docker).
- **Tốc độ đọc dòng Oracle** (`OracleProvider.TuneCommand` / `TuneReader`, gọi từ `ExecuteOnAsync`, `StreamAsync`, `ReadRowsAsync`): `FetchSize` = `RowSize` × số dòng cần (tối đa 5.000 dòng, 16 MB) thay cho 128 KB mặc định, và `InitialLOBFetchSize` / `InitialLONGFetchSize = -1` để LOB về cùng dòng. `TuneReader` không được ném exception. PostgreSQL không cần: Npgsql đọc theo luồng.

## Bất biến bảo mật

- Kestrel chỉ listen `IPAddress.Loopback`; mọi `/api/*` cần header `X-DbStudio-Token` (chỉ `--dev` mới bỏ).
- Password chỉ ở dạng plain trong RAM; ghi đĩa qua DPAPI `CurrentUser`; API chỉ trả `ConnectionDto` (`hasPassword`), không bao giờ trả password. Không log SQL kèm connection string/password.
- Dữ liệu người dùng nằm ở `%APPDATA%\DbStudio\connections.json` — không đụng tới file thật khi thử nghiệm (đặt `DBSTUDIO_DATA_DIR` sang thư mục tạm).

- **Tiền tố biến** áp dụng cho biến local, tham số, private field (`_strFile`, `_dicCache`), lambda param, biến catch, React state/ref/props dữ liệu.
